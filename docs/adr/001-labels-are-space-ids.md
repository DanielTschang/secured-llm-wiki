# ADR-001：標籤是來源 space ID 的集合

- 狀態：已採納
- 日期：2026-09-28

## 背景

系統需要一種方式標示每筆資料「誰可以看」。候選做法有三種：以部門名稱當標籤（OPC、CD）、讓 LLM 依內容判斷機密等級、或直接使用來源在平台上的權限單位。

黃光領域的機密性取決於出處而非字面內容：一句看似教科書等級的敘述，出現在 OPC team 的課程中，就透露了該 team 關注的重點。內容判斷因此不可靠，也無法驗證。

內部知識管理平台以 space 為權限單位，每個頁面恰屬於一個 space。

## 決策

1. 標籤是 space ID 的集合（`frozenset[str]`），而非部門名稱。
2. 原始頁面的標籤恰為 `{所屬 space_id}`，由同步服務依平台回傳的 metadata 確定性地指派。
3. 任何衍生物的標籤 = 其所有輸入標籤的聯集，由程式計算，不由 LLM 產生或修改。
4. 公開 space 在標籤模型中沒有特殊地位；它只是所有使用者都讀得到的 space。
5. 主題（topic）與標籤是不同欄位，主題永遠不參與權限判斷。
6. 本系統假設平台只有 space 層級的權限。若同步時發現頁面帶有頁面層級的限制，該頁面進入隔離區、不 ingest，直到設計擴充。

## 影響

- 權限模型與平台完全一致，不需要維護部門與 space 的對應表。
- 一個 team 有多個 space 時，標籤仍以 space 為單位；「team」只用於介面分組。
- 頁面搬移到其他 space 等同於刪除後重新 ingest，不原地修改標籤。
- 無法表達「頁面只給 space 中部分人看」；目前以隔離處理，屬已知限制。

## 考慮過的替代方案

- **部門名稱當標籤**：需要額外維護對應表，且 team 與 space 並非一對一。
- **LLM 判斷機密等級**：不可靠、不可驗證、會隨模型變動。
- **公開內容用空集合表示**：在 space 模型下公開 space 本身就是一個 space，沒有必要引入特例。
