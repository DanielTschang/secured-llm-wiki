# ADR-005：以投影片為最小閱讀單位，圖文一起判讀

- 狀態：已採納
- 日期：2026-09-28

## 背景

平台上的內容多為內部課程教材，由投影片轉成的 markdown，形式是「圖配字」：

- 圖的意義由旁邊的文字決定（例如同一張 Bossung curve，文字決定重點是 iso-focal 偏移還是 DOF）。
- 文字常是片段條列，要看圖才完整。
- 關鍵資訊常只存在於圖中：製程窗口、overlay map、SEM 影像、規則表格的截圖。
- 同一概念在多門課、多個年度版本中重複出現，數值可能不同。

常見做法是先把圖片抽出、單獨產生說明文字，再當一般文字處理。這會讓圖失去文字賦予的意義。

## 決策

1. **閱讀單位是投影片**：依 markdown 中文字與圖片引用的原始順序切分，每張投影片包含一段文字與其圖片，交錯送入地端 VLM。
2. **課程是脈絡單位**：判讀時附上課名、前一張投影片的重點與累積術語表；投影片筆記再以整門課為單位整合。
3. **依圖型判讀**：先分類圖型（`bossung_curve`、`process_window`、`meef_plot`、`overlay_vector_map`、`wafer_map`、`sem`、`schematic`、`screenshot`、`table`、`bar_chart` 等），再套用 `schema/figure_guides/` 中對應的判讀指引。指引屬於格式規範，全公司共用。
4. **數值來源分級**：從圖上目測判讀的數值標記 `numbers_from_figure: true` 並視為近似值；文字、表格、截圖中明確寫出的數值標記為 `false`。
5. **原圖進入 wiki**：space wiki 頁嵌入最具代表性的原圖並標註來源投影片，讓讀者可以自行驗證。
6. **grounding 驗證包含圖片**：驗證敘述時，同時提供原始投影片的文字與圖片。
7. **版本處理**：同一概念有多個課程版本時，以最新版本為現行內容，舊版本說法寫入「版本演變」段落。
8. 圖片的標籤與所屬頁面相同，只能經由驗權端點提供。

## 影響

- 需要地端部署的 VLM，並能處理高解析度圖表（必要時切塊）。
- ingest 成本高於純文字處理；以版本 hash 做增量處理控制成本。
- 圖型指引需要隨新的教材類型持續擴充。
- 檢索可額外使用圖片 embedding，支援以圖的內容描述來查詢。

## 考慮過的替代方案

- **圖片單獨產生說明再合併**：失去圖文之間的語意關係。
- **只處理文字、忽略圖片**：遺漏大量只存在於圖中的知識。
- **以整個頁面為判讀單位**：輸入過長，圖文對應關係模糊。
